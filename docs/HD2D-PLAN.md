## 1. 目标与已确认规格

采用 **二维玩法逻辑 + 真正的 3D 世界场景 + 全新像素素材/人物 + 原生 2D HUD**。重点是自然可行走的武侠小镇，不是强景深的微缩模型，也不是给旧 2D 整图加滤镜。

当前地图为 100×60 格，含 7 栋主要建筑、玩家与 7 位 NPC、野狼/山贼/头目；范围适合先做完整样板，再迁移全地图。玩法坐标、碰撞与日程不依赖显示技术，因此不需要重写游戏系统。

### 1.1 「全面迁移」交付定义

| 项目 | 已确认目标 |
|---|---|
| 覆盖范围 | 清溪镇、东山林地、后山崖全部使用 3D 世界；不遗漏现有家具、道具、人物或怪物 |
| 美术方向 | 自然像素武侠、江南山麓小镇；青灰瓦、灰白墙、深木、旧石与青苔，低饱和灰绿与少量暖色店招 |
| 资源重制 | **全部世界素材重新制作**：地面、建筑、草木、家具、玩家、NPC、怪物及基础动画；旧世界图片仅临时占位或作原版对照 |
| 素材形式 | 直接生产可用于 3D 的平铺材质、正视组件、透明底布景与人物图集，不先批量做整栋透视概念图 |
| 建筑 | 真实墙体、坡屋顶、屋脊与屋檐厚度；一层为主，客栈/武馆主堂略高；城墙、镇门和主要崖体有体积 |
| 人物 | 细颗粒像素；人形约 4～5 头身，保留身份、年龄与职业特征；玩家/NPC/怪物均制作八向待机与行走，野兽保持自身解剖比例 |
| 人物显示大小 | 实际 1440×900 窗口、2×世界缩放下，人形主体先按约 64～80 屏幕像素高做样板，与门、屋檐、道路一并验证后锁定 |
| 镜头 | 透视镜头；P1 默认垂直FOV35°／俯角38°／方位30°，支持30°–40°FOV、30°–65°俯角与360°绕转、一键复位；保留跟随，1×/2×/3×在玩家脚点深度校准，远处自然缩小；正交仅供对照，P1规格已获认可，P2沿用 |
| 遮挡可读性 | 玩家及当前交互目标受挡时，只将其前方建筑/布景中覆盖全身包络的局部区域柔边透明；同一墙段/屋面其余部分保持正常，双目标各自过渡，不改变角色深度测试 |
| 光照 | 暖日光、冷环境光、实时投影，克制薄雾与轻景深；根据现有游戏时钟做轻量昼夜变化，夜间仍能认路和辨人 |
| 环境动态 | 少量草木轻摆、池塘细波、灯笼/布幌微动；不以满屏粒子、强闪光制造氛围 |
| UI/玩法 | 既有 HUD、对话、背包、商店、武学、战斗面板与小地图保留，仅作必要衔接；后端、存档、接口、玩法规则不变 |
| 性能与平台 | Linux/Mango 首验；1440×900、2×下，RTX 4050 标准档与 Radeon 780M 轻量档均以稳定 60 FPS 为目标；Windows 后续单列实测 |
| 制作节奏 | 一名完整八向角色 + 一栋房屋 + 道路/树/灯 → Godot 实测 → 用户认可样板并锁规格 → 量产 |

最终主入口默认使用 HD-2D；标准/轻量档共用立体场景。旧 2D 仅供迁移对照，最终切换须在完整验收后进行，不提前删除可运行基线。

### 1.2 明确不做

- 不改后端业务、数据库、LLM/记忆系统、战斗数值、NPC 智能或日程；不在前端伪造结算。
- 不改为 3D 寻路/物理移动，不新增跳跃、室内地图、楼层通行、多地图、自由飞行或移动端适配。P1 按用户要求采用透视镜头，开放FOV、手动俯角与左右绕转，不提前接入主游戏。
- 不重设计 HUD/面板，不加入独立战斗演出、职业动作库、天气、季节或昼夜玩法；**轻量昼夜仅影响外观**。
- 不复制《逸剑风云决》等参考游戏素材，也不承诺同等商业美术完成度。
- 不用平滑高清插画、全屏锐化或过度景深代替一致的像素素材。

### 1.3 分工与变更边界

用户确定画面目标与验收门槛；助手负责素材规格、提示词、源图路径、加工流程，以及图集/帧数/材质/shader/光影参数的实测调优。默认源图由用户生成；本轮已明确授权助手用 **pi-image-gen** 制作首批样板源图，仍须先记录提示词/路径，样板认可后才量产。

不再逐项询问可在目标内调优的技术参数；但明显改变视觉方向、削减已确认功能、放宽性能门槛或扩大后端范围，必须重新确认。用户本轮已认可 P1，后续按锁定规格推进；最终入口切换仍保留 P5 验收。

## 3. 渲染器与画质预算

**优先采用 Forward+；两档优先共用同一渲染后端，不以运行时换后端实现画质开关。** 这是首轮技术路线，最终须由双 GPU 原型结果证明。

- **标准**：单主方向光/实时阴影、冷环境填充、轻薄雾、少量局部发光与轻景深；SSAO 仅在同场景对比有收益时启用。
- **轻量**：保留全部建筑/人物、八向动画、局部遮挡虚化、昼夜语义和环境微动；降低阴影精度/距离、灯数量、微动密度/更新频率，关闭景深及额外屏幕空间效果。不退回旧 2D，也不静默删功能。
- 首轮不依赖 SDFGI、SSR、体积雾、大量动态阴影灯或 TAA/FSR；避免对细像素造成重影/模糊。
- Compatibility 支持核心 3D，但缺少本计划使用的内置景深；若发生引擎启动回退，明确报告后端与特效差异，单独验证，不算标准档通过。
- 同一场景的 Mobile 路线可在 Forward+ 无法满足预算时评估；不得未经确认把降低视觉/功能目标当作成功。
- Linux 首验；Windows 保留可移植实现，后续单列验证。Linux 成功不能代表 Windows 已通过。

## 4. 目标架构与硬约束

```text
Main（Control：既有输入、HTTP、HUD、面板）
├─ TownWorld（Node：二维玩法状态与确定性日程）
├─ WorldArea（Control：原有世界显示区域）
│  ├─ SubViewportContainer
│  │  └─ SubViewport（与 WorldArea 等大，3D 独立世界）
│  │     └─ TownView3D（Node3D：只读 TownWorld 状态）
│  │        ├─ Camera3D（透视；P1 手动FOV／俯角／绕转）
│  │        ├─ WorldEnvironment / 昼夜 / 灯光
│  │        ├─ 地面 / 建筑 / 城墙 / 崖体 / 布景 / 微动
│  │        ├─ 玩家 / NPC / 怪物（八向像素动画）
│  │        └─ 遮挡检测 / 玩家与当前目标触发的局部虚化
│  └─ WorldOverlay（Control：原生名字、气泡、地点名）
└─ 原生 HUD / 小地图 / 对话与战斗面板
```

### 4.1 二维逻辑不动

- 保留 `actor_pos: Vector2`、人物身份/移动状态、`npcs`、`mobs`、气泡状态等；`TownWorld` 仍是玩法位置的唯一来源。
- 保留 `can_walk`、`nearby`、`region_name`、`apply_state`、`tick_schedule`、`schedule_position`、`show_bubble` 的语义。
- 移速、脚部碰撞、NPC 感知/38px 交互、17px 遇敌、建筑外扩 32px 门口区与复活落点修正不变。
- API 上报原二维 `x/y`；3D 节点不回写投影位置，不改变服务端日程常量，不增加位置轮询。
- P1 的 WASD/方向键按镜头地面 right/back 轴转换为原二维移动向量，速度与归一化不变，仍用二维脚部碰撞。八向动画按实际位移在镜头轴上的方向选帧，停步和旋转镜头保留相对镜头的朝向。P2完整客户端已接入此映射，对话冻结/恢复契约不变。
- 当前没有点地移动或鼠标选人；本轮不新增操作。“当前目标”来自既有交互选择/对话状态，不新增锁定玩法。

### 4.2 投影、人物脚点与镜头

- 世界仍为 `1600×960`、逻辑瓦片 16px。集中映射 `Vector2(x,y) → Vector3(x*s,h*s,y*s)`，`h=0` 为地面；建议 `s=1/16`，显示高度不上传服务端。
- 当前 P1 按用户选择改为透视，默认垂直FOV35°／俯角38°／方位30°。FOV限制30°–40°、俯角30°–65°、方位绕转360°；Home复位三项参数，保留J预设和跟随，不新增自由飞行，P2完整客户端已沿用该规格。`KEEP_HEIGHT` 下玩家脚点参考深度 `d = viewport_height*s/(2*zoom*tan(FOV/2))`；相机距离加上玩家相对构图焦点的深度差，保留偏上构图与1×/2×/3×参考比例。固定FOV下通过相机距离缩放；远近物体自然改变屏幕尺寸，不对所有人物做屏幕等高归一。正交仅保留 `--projection orthogonal` 同场景对照。
- P1 移动相对镜头：W/S 沿地面远/近方向，A/D 沿镜头左/右方向。人物竖直贴片始终随相机方位朝向镜头，保留八向行走图集；只旋转镜头不改变停步动画行，移动后按实际镜头相对位移更新。脚点修正、标签和稳定全身包络同步相机 right 轴；灯笼 CPU 射线/alpha 空间随固定 Y billboard 转动，新的树干/体积树冠保持真实世界方位。相机吸附、偏上构图和透视远近比例不变。
- 人形 4～5 头身与 64～80 屏幕像素主体高度是**样板目标**，不是固定源图画布尺寸。原图分辨率、像素密度和视觉世界高度分别定义；32px 旧帧不再限制新素材。
- 人物/灯笼等朝向镜头的竖直布景用 `BILLBOARD_FIXED_Y`，高度按 `1/cos(pitch)` 补偿竖直平面缩短，仍保留真实透视的远近大小变化；脚点沿世界 UP 对齐。树干/体积树冠是固定世界几何，不做 billboard 或俯角补偿。禁止人物全轴 billboard 或沿 `camera.up` 抬中心，以免上半身插墙。
- 八方向每帧单独记录/校准脚底基线和有效边界，不假定画布末行是脚底；不得走路换脸、换衣、跳脚点或忽大忽小。人体左右不对称道具不能随意镜像。
- 相机在玩家脚点参考深度的像素网格上吸附，只处理显示，不量化日程/碰撞；保留既有偏上构图。人物/中文清晰和运动稳定优先，不承诺全画面各深度或斜面纹理像素逐个等宽方正。
- 合理 near/far 与边界补景；1×或宽窗口时不能看见空白世界、裁掉高屋顶。P1 在原 1600×960 范围内开放单栋样板空地，清除无可见几何的旧障碍；这不改变正式地图/服务端可走性。

### 4.3 原生视口与 UI

- 子视口与 WorldArea 实际像素尺寸一致，`stretch_shrink=1`，不先小画布渲染再放大。HUD、名字/气泡不进入世界景深。
- 使用不透明子视口背景；Godot 内置景深不支持 `transparent_bg=true`。
- 投影后的局部屏幕坐标统一转换到 WorldOverlay；人物有效边界投影四角取包络，兼容透视下近端肩部变宽；镜头后方/完全离屏隐藏标签。字号原生栅格化，避让 HUD/边缘。
- Main 统一输入，容器不抢焦点/重复转发；保留面板禁行、滚轮、中文输入、SSE、忙碌/错误提示、状态版本与断线战局恢复。
- 普通姓名/气泡不无条件透墙；玩家和当前目标在局部虚化后恢复可读。不得关闭角色深度测试实现“看得见”。

### 4.4 遮挡人物部分的局部柔边虚化

本轮用户改选局部方案，替代此前 B 整构件渐隐。这里的“虚化”采用柔边半透明：只在被挡人物周围逐渐降低前景像素的不透明度，不添加全屏模糊。

- 只保护玩家和至多一个当前交互目标，普通 NPC/怪物不独立触发。稳定全动画包络仍以左右/中心 × 脚/躯干/头部 12 点检测，透视射线从近裁面向采样点收束，收集人物前方全部遮挡层；图片 alpha 空洞不选，双面射线形状仍须 `backface_collision=true`。
- 射线分组只决定哪些实例需要辅助，不再让整组外观一起消失。客栈所有静态几何已合并为一个 `structure` 网格／`inn/structure` 组，共用一套双面视觉射线形状；同材质合为一个Surface。每个目标将稳定全动画包络投影到原生 3D 视口，生成覆盖完整身体的圆角矩形和柔边过渡；墙、瓦、门窗、屋檐只有遮罩内的像素变淡，同网格远处/人物后方表面保持原样。灯笼因固定Y朝向与摆动独立为 `inn/lantern/0`、`inn/lantern/1`，无须跟墙段拆分。
- shader 同时比较每个 fragment 的世界位置和人物固定 Y 竖直平面，只作用于人物前方；同一 mesh 的背后表面也不应跟着透明。角色保留正常深度测试，阴影通道保持完整几何。
- 两目标使用独立位置、强度和恢复计时，按最大值合并局部区域；移除目标只恢复其自己的区域，不清除玩家区域，也不把两人之间的墙一并透明。30Hz 检测、约0.18s淡入，解除后保留0.25s，再约0.35s恢复；遮罩位置每帧更新，避免相机转动时出现明显滞后。完全虚化时P1普通布景每表面保留4%不透明度，闭合树干／叶簇及P3闭合多Surface模型为1%，避免极端俯角／3×时多层前景叠加压低人物对比；遮罩外／人物后方与阴影通道仍完全正常。身体像素保留90%／线性信号65%的判定不变。
- GPU 验收先关闭辅助检查真实客栈硬遮挡，再开启检查全身可读；同位置有人/无人、前景有/无差分，至少90%参考身体像素保留至少65%线性光对比信号。新增断言检查同墙远端不变、柔边过渡、分离双目标中间墙不变、单目标退出时独立恢复；旧“整构件而非局部洞”断言已被替换。
- 两档共用局部虚化语义，不新增进入建筑/锁定玩法，不改变正式碰撞、日程或交互。P1、P2与P3当前GPU／交互证据分别见§9.2、§9.3、§9.4，历史B结果只保留为历史记录。

### 4.5 昼夜与环境微动

- 复用现有游戏时钟/anchor 本地推算光照，不加轮询、不修改服务端时间或日程。日间温暖、黄昏柔和偏暖、夜间冷色填充和灯笼发光；过渡连续、夜景可读。
- 两档都有昼夜；不要求每盏灯拥有实时阴影，灯光数量/精度按预算调优。
- 草木摆动、水面细波、灯笼/布幌微动克制，不造成道路摇晃、人物误识别或布景脚底滑动；降低密度不能遗漏必要道具。
- 不增加天气、季节、浓粒子雾、真实水体反射/折射或职业动作库。测试不同时间用隔离样板/客户端测试快照，不修改真实存档与后端时钟。

## 5. 全新素材与全场景迁移

### 5.1 3D 分层与逻辑占地

1. 保留确定性网格/种子与装饰布局，使用**新地形材质**输出纯地面；训练场/路面水平细节可烘焙，不为 6000 格各建 Node。
2. 建筑、树木、井、家具、城墙从旧静态图移出，改独立实例；共享材质/mesh，不每帧重建。
3. 七栋房屋按原占地构建台基、墙、屋顶、门窗；一层为主、主堂略高，靠材质/门面陈设区分职业。屋檐外挑不堵通路。
4. 镇门保留通行口，崖体符合不可走区域；不让仍可走的路被视觉模型盖住，不新增坡道玩法。
5. 竖直布景、水平小物和体积物分类；大石/崖体优先几何体，池塘独立水面与岸边，保持现有地形边界。

本轮用户要求重做树木，原三张整树交叉贴片不再使用。当前P1树由 `tools/build_hd2d_tree.py` 在Blender独立 `XIA_P1_Pine` 场景生成：根盘、弯折／分叉／锥缩树干为一个Mesh，14个闭合的横向多叶瓣松针枝冠合并一个Mesh；每树2Mesh／2Surface／6336三角形。叶簇从枝干骨架组织前后、疏密和明暗，避免侧视整卡片和高俯角十字形。像素树皮单独制图，不再复用木板纹；叶表为6色松针簇，法线选投影方向保持各面纹素尺度，3～4级漫反射与真实主光／阴影组合，无高光／常态自发光。两树共享GLB和材质，固定世界几何，树冠shader保留轻摆。树脚只使用原二维树格，视觉根枝不改变玩法占地。可重建源／运行资产为 `asserts/hd2d/props/pine.blend`（忽略）及 `assets/hd2d/props/pine.glb`／`pine.json`；导出检查闭合边／退化三角形，Godot用两套双面layer=2视觉射线形状，仍按一棵树一个局部虚化组。旧 `props/tree.png` 仅保留对照，不再被树模型加载。

P1 可走范围由 `scripts/hd2d/fixture_layout.gd` 在离线对象内准备：原1600×960边界、脚部碰撞和客栈192×128占地保留，只保留可见客栈/两棵树的阻挡，并铺客栈四周环路接南侧道路。未显示的其余建筑/井/池/城墙/树林/崖不再形成隐藏碰撞，正式游戏的原始网格和可走性冻结契约仍保留。

### 5.2 新资源生产规范

- 新源图放 `xia-ai-town/asserts/hd2d/`；`tools/build_art_assets.py --hd2d` 输出 `assets/hd2d/` 及元数据。P1 客栈由 `tools/build_hd2d_house.py` 重建；P3 其余6栋建筑、29类家具／草木／岩石及镇门／灯柱由 `tools/build_hd2d_environment.py` 导出37个GLB和 `environment.json`。本批复用已认可的全新像素材质，不新增或手改PNG；运行不要求安装Blender，源库在忽略目录。
- 旧世界资源仅占位/对照，不能作为最终素材或反向限制精细度；保留旧 UI 资源和迁移期原版的可重建性，不无意覆盖它们。
- 优先生产青灰瓦、灰白墙、深木、旧石等平铺材质，正视门窗/装饰和透明底人物/布景；不把整栋透视插画贴满多个面。
- 光照中性、可接受动态灯影；不烘焙强烈固定方向的环境阴影、夜景光晕或地面投影。细像素颗粒、调色板、有效比例要跨组件一致。
- 平铺检查接缝；透明底检查残色、裁切、溢色；图集元数据包含方向/动画、帧时序、脚点、有效边界。尺寸和帧数由完整样板锁定，不强塞旧 4×4/32px 规范。
- 人物优先 nearest、受控 alpha cut；斜地面/屋顶分别实测过滤与 mipmap，处理图集边界渗色。不得用全屏模糊或去掉必要细节掩盖问题。
- 常态布景保留深度测试，优先合适的 alpha cut/深度方案；局部虚化的混合路径必须另测排序/阴影，不假定常态 alpha cut 能自动实现连续淡化。
- 角色接地阴影与实时投影须实机验证。P1 使用 `actor_shadow.gd` 的仅投影人体体积（头/躯干/袍/四肢/背剑合成单mesh）取代竖直Sprite投影，另保留水平柔边接地面；真实主光决定方向/长度，体积不随相机俯角伸缩，不加入碰撞/遮挡射线。九个姿势mesh共享，按八帧步态切换；两画质保留。新图中性光照不代表人物可以悬浮或过暗。

### 6.2 静态场景编辑与离线重建

固定节点层级以 `scenes/hd2d/` 的 `.tscn` 为运行入口，不再由 `TownView.setup()`／`Scenery.build()` 在启动时生成全镇几何：

- `world_presenter.tscn` 保存原生视口、世界标签层和视角面板；容器不做整帧拉伸，脚本按实际世界区域尺寸设置子视口。`prototype.tscn` 同样保存样板HUD／中文输入测试面板／相机控制面板，2D基线入口仍保留。
- `town_view.tscn`／`prototype_view.tscn` 保存相机、灯光实例、全镇／样板布景、玩家和人口挂点。`actor.tscn` 保存Sprite、仅投影体积与接触影；NPC／怪物仍按服务端集合增删，但实例化这个预制体而不逐个构造组件。
- `town_scenery.tscn` 保存全部建筑、家具、树林、城墙、池岸、山崖、灯笼、局部灯以及双面layer=2视觉射线；`prototype_scenery.tscn` 保存原P1固定布局。GLB以可编辑子实例引用，**不复制模型顶点或引用 `.godot/` 缓存**；合批地形、射线和九个共享人物投影姿势放在 `assets/hd2d/static/` 的 `.res`，材质／纸墨主题为 `.tres`。
- `lighting.tscn` 保存Environment、主光和导出的CameraAttributes资源。昼夜、画质、镜头、八向步态、局部虚化和灯笼固定Y补偿仍是运行逻辑；运行时仅建立查找索引／每世界独立的可变材质副本。灯笼射线随俯角变化仍需更新，普通静态构件使用已保存形状。
- 在Godot打开 `town_view.tscn` 可查看全镇；编辑具体固定布景打开 `town_scenery.tscn`，编辑人物组件打开 `actor.tscn`。视觉位置／模型尺寸不能替代原二维碰撞与交互占地。改GLB几何后须同步重新烘焙视觉射线，移动实例则射线随节点一起移动。

原构建代码移到 `tools/hd2d/`，仅供显式离线重建，不由游戏或测试工程启动时调用。固定地图／模型变更后可以在根目录执行：

```bash
godot --headless --path xia-ai-town --script res://tools/build_hd2d_scenes.gd
```

该命令覆盖 `town_scenery.tscn`／`prototype_scenery.tscn`／`pine.tscn` 与派生静态资源；**不要把它当成自动启动步骤**，直接编辑上述生成场景后应先保留改动，再决定是否重新烘焙。人物／灯光／视口／面板等手工源场景不被该命令覆盖。已有隔离探针只改为加载相应PackedScene，断言边界没有放宽。

### 7.1 逻辑与现有接口

```bash
SCHEDULER_ENABLED=false GODOT_BIN=/usr/bin/godot \

```

- 对话 SSE token/reset/done、送礼、切磋、学艺、动作气泡、等待/错误、断线/战局恢复不回归，不增加 LLM 请求或位置同步。

### 7.2 真实 GPU 画面与输入

| 类别 | 用例与判定 |
|---|---|
| 人物/动画 | 所有八方向待机/行走及斜走/停步；同一身份、服饰/武器、比例、步态和脚点稳定，野兽姿态合理 |
| 真实几何遮挡 | **关局部虚化**绕建筑/树/围栏；脚点不浮、上身不插墙，不把合理屋后遮挡判成 bug |
| 墙体探针 | 明确法线/可见侧，墙外 1 世界像素、墙内 4 世界像素独立样本，检测外侧误削头/内侧穿透 |

### 7.3 持续真实交互性能

固定路线：镇口 → 客栈 → 三馆 → 池塘/破庙 → 镇门 → 林地 → 山崖 → 回镇。每个 GPU 对应画质连续至少 15 分钟，穿插行走、缩放、SSE 对话/搭话、背包/商店开关、送礼/学艺、战斗/返回；反复走相同区域检查累积，不用加载后退出或空场景 FPS 代替。

- 同设备、实际窗口/缩放/路线比较旧 2D 与新画面；报告外层 1440×900 和 HUD 占用后的实际 WorldArea 尺寸，不误报为同尺寸世界 framebuffer。
- 分离首次资源/shader加载与预热稳态，记录 FPS、帧时间 p50/p95/p99、>50ms 卡顿、进程 RSS、可取得的显存/Godot内存、节点数/draw calls。
- **已确认目标：RTX 4050 标准档、780M 轻量档稳定 60 FPS。** P1 可校准技术预算和诊断阈值，不能未经用户同意改成“核显可运行即可”或只用平均 FPS 通过。
- 先优化材质共享、构件 overdraw、灯影预算、动态更新等；若仍不达标，报告实际结果并重新协商，不静默降目标或删八向/昼夜/渐隐。
- 实际玩法配置下测对话；记录本地 Ollama/外接 API 及其负载，Godot与模型占用分列。不得停掉实际服务只测空地图后声称交互性能通过，不改模型配置来替前端达标。
- 预热后至少重复三轮，RSS/显存不得持续单调增长；使用时间序列，不拿首尾两点或加载后退出替代泄漏检查。
- Mango 自动平铺时，按自己测试进程 PID 找窗口，用 `mmsg` 仅将该窗口切浮动；不改全局布局或其他应用。

通过须同时满足：逻辑回归全绿、画面/动画/遮挡/日夜/输入无阻断缺陷、双 GPU 性能目标有实测证据，以及用户认可可运行样板与最终同场景对照。Windows/其他显卡未测明确标注。

- 删除P2环境方块／旧家具贴片构造入口，HD-2D环境不再加载旧世界地形、房屋或道具atlas。旧2D画布及其静态像素hash继续冻结。日常完整客户端气泡检查先靠近当前NPC，再检查显示／monotonic到期，避免日程踱步把NPC移出38px后，误将正确的遮挡隐藏判作气泡故障；未修改普通NPC透墙规则或输入法链路。
